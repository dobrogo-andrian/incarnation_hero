# 3 Модель даних і контент-пайплайн

## 3.1 Принцип

**Формули живуть у коді, коефіцієнти й контент — у даних.** Скриптової мови не робимо. Умови й ефекти — це скінченний набір типізованих операцій, які розширюються в C# за потреби. Це свідомий компроміс: трохи менше гнучкості, але валідація, автодоповнення і ніяких рантайм-помилок у скриптах.

## 3.2 Каталог даних

```
/content
  /balance        — коефіцієнти формул: combat.yaml, cultivation.yaml, time.yaml, injuries.yaml, economy.yaml
  /cultivation    — етапи, методи, корені, типи тіла
  /knowledge      — фоліанти, техніки, стихії
  /combat         — вороги, групи ворогів, зброя, архетипи AI
  /world          — шаблони зон, місць медитації, сект, магазинів, імен
  /events         — події (за контекстом: training/, travel/, meditation/, settlement/)
  /rumors         — шаблони чуток
  /injuries       — типи серйозних травм
  /items          — пігулки, ліки, камені, предмети
```

## 3.3 Ідентифікатори і теги

- Кожен об'єкт має стабільний рядковий ID: tech.spear.piercing_dragon, enemy.beast.iron_boar. Стан посилається на контент лише через ID.
- **Теги категорій** обов'язкові для всього, що дає резонанс душі: weapon:spear, element:fire, school:body_tempering, lang:ancient. Резонанс рахується за тегами (розд. 4.8).

## 3.4 Приклади форматів

Техніка:

```yaml
id: tech.spear.piercing_dragon
name: { uk: "Пронизливий дракон" }
tags: [weapon:spear]
requires: [weapon:spear, two_arms]
max_level_source: foliant          # рівень дає лише фоліант
action:
  cost: { body_energy: 2, combat_qi: 15 }
  range: { min: 1, max: 2 }
  pattern: line                    # гекс-патерн цілі
  effects:
    - damage: { base: weapon, mult_per_level: 0.12, mult_per_mastery: 0.08, qi_density: true }
    - push: { hexes: 1 }
```

Подія:

```yaml
id: evt.travel.wounded_disciple
context: travel
weight: 10
once_per_run: true
conditions:
  - zone_danger: { min: 2 }
  - stat_gte: { stat: perception, value: 8 }   # опційна гілка, див. варіанти
nodes:
  start:
    text: { uk: "Біля дороги лежить поранений учень секти {sect.gen}…" }
    options:
      - text: { uk: "Допомогти (1 тиждень)" }
        effects: [ { time: 1 } ]
        outcomes:
          - weight: 6
            effects: [ { reputation: { sect: "{sect}", delta: 5 } }, { add_rumor: rum.tpl.hidden_cave } ]
          - weight: 4
            effects: [ { start_combat: { group: grp.bandits.ambush_t2 } } ]
      - text: { uk: "Пройти повз" }
        effects: []
```

## 3.5 Локалізація

- Текст пишеться українською **прямо в YAML** (uk:), бо це найзручніше для єдиного автора.
- Скрипт збірки витягує тексти в таблиці /loc/*.csv зі стабільними ключами (<id>.<поле>). Переклади на en/zh живуть у таблицях. Відсутній переклад повертає ключ або українську з позначкою.
- Ядро повертає **ключі з параметрами**, а не готові рядки. Резолвить текст шар представлення.
- **Системні й UI-тексти** (причини відмови, написи інтерфейсу) живуть у `/content/strings/*.yaml` як об'єкти `str.*` з полем `text: { uk }`. Їхній ID і є ключем (D20).
- **Множина.** Українські тексти формулюємо без узгодження з числом («Тижнів: 5»), модуля правил множини поки немає (A9). Для en/zh рішення приймаємо перед етапом 5.
- **Відмінки.** Генератор імен видає набір відмінкових форм. Шаблони посилаються на {npc.nom}, {npc.gen}, {npc.dat}… Для китайських транслітерацій правила відмінювання прості й генеруються автоматично.
- Перевірка готовності: на етапі 5 проганяємо псевдолокалізацію (подовжені рядки) і тестовий китайський рядок у кожному вікні.

## 3.6 Валідація і перезавантаження

- **Валідатор** запускається при старті гри і як CLI-команда. Він перевіряє:
   - схеми;
   - існування всіх ID, на які є посилання;
   - досяжність вузлів подій;
   - відсутність тегів без категорії;
   - діапазони значень;
   - наявність тексту uk скрізь.
- **Пакування (D51):** `/content` вбудовано в збірку Core як ресурси (`ContentFiles.Embedded`), тож редактор і експортована гра читають ті самі файли, а гравець не бачить YAML. Тести й Sim.Cli читають теку з диска (`--content`), тест стежить, щоб вбудований контент збігався з текою.
- **Hot reload у dev-збірці:** перезавантаження контенту без перезапуску. Стан посилається лише на ID, тому це безпечно в межах сумісних змін.
- **Як додати новий об'єкт:** створити YAML у відповідній теці → запустити валідатор → hot reload → перевірити в debug-панелі (заспавнити подію, бій або предмет) → прогнати Sim.Cli, щоб побачити, чи об'єкт з'являється і як впливає на метрики.
